Getting started

Pull the versioned TimeboardApp image from GHCR and run it with Docker Compose. The default URL is http://localhost:8888.

Prerequisites

  • Docker Engine with the Docker Compose plugin
  • A writable directory for persistent settings.yml and the SQLite database
  • The external Docker networks configured in .env
  • GHCR authentication if the package is private
Published image
ghcr.io/paulkakell/timeboardapp:00.13.00 is the default image. Compose pulls it rather than building locally.

1) Prepare the environment

Copy the sample environment file and adjust the host port, data directory, container alias, and Docker network names:

cp .env.example .env

The default external networks can be created once with:

docker network create net_internal
docker network create net_external

If the GHCR package is private, authenticate before pulling:

echo "$GHCR_TOKEN" | docker login ghcr.io \
  -u YOUR_GITHUB_USERNAME --password-stdin

2) Pull and start the stack

docker compose pull
docker compose up -d

Container port 8888 is published to the host port specified by PORT.

3) Open the UI

Open:

  • http://localhost:8888

If you mapped a different host port, use that port instead.

4) Sign in on first run

TimeboardApp generates an admin account and prints its initial password to the container logs. The Compose service name is app: 

docker compose logs -f app

You can reset the password through the CLI:

docker compose exec app python -m app.cli reset-admin

Production and demo on one host

Use a unique CONTAINER_NAME, host port, and data directory for each stack:

# Production
PORT=3010
CONFIG_DATA=/srv/timeboardapp/production
CONTAINER_NAME=timeboardapp

# Demo
PORT=3011
CONFIG_DATA=/srv/timeboardapp/demo
CONTAINER_NAME=timeboardapp-demo
Reverse proxy routing
On a shared Docker proxy network, route to timeboardapp:8888 and timeboardapp-demo:8888. Do not route to the shared Compose service alias app.
